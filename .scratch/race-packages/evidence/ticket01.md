# S15 01 — completed package selection foundation

Canonical ticket: [#53](https://github.com/rociodevenish/BoxBox/issues/53). Implementation is awaiting integration review; the issue remains open.

Campaign creation now records a neutral baseline library and version selection for every frozen team/event preset. Legacy neutral preset context has an explicit `explicit-neutral-preset-migration-v1` mapping. Unknown legacy identities fail rather than receiving zero modifiers. `RacePackageVersion` records stable identity, immutable version, completed availability, strengths, compromises, circuit applicability, provenance and refinement history. The neutral entry is free, completed and applies to all circuits.

`RacePackages.Select` accepts exactly one completed version; unknown, pending and inapplicable versions fail. An explicit neutral selection can replace an unavailable draft. Selection is separate from development and its ledger/opportunity. The authorised private preparation endpoint uses existing assignment authority, revision checks, command fingerprints, persisted receipts and private/open-household notifications. Final-ready must be reopened before changing a selection; qualifying locks both setup and package. One historical practice assessment remains attached to its assessed setup/package, with its original selected identity and name displayed. Changing selection never grants another assessment.

Composition retains original Base Car/permanent source values in `EffectiveWeekend.Source`, applies only the selected package once before setup, and preserves package-composed car sources for wet and Reliability consumers. Library additions/refined versions cannot change an existing effective snapshot. S14 effective event snapshots remain authoritative and are not reconstructed from mutable catalogues.
