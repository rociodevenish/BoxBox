# S15 02 — specialised package creation

Canonical ticket: [#54](https://github.com/rociodevenish/BoxBox/issues/54). Implemented from integration `0853d390b05adcb58065fa07b1813743a61a6e84`; awaiting independent review, with the issue left open.

Five provisional templates now offer low-drag, downforce, tyre-management, cooling/reliability and mechanical-grip alternatives. Prices are 14–18 integer credits before one bounded staff discount (maximum 3; absolute floor 8). Each template prints its supported detailed strengths, compromises, applicability, timing and retained credits. Strengths are bounded below the +6 per-attribute package cap and compromises at the -3 creation floor; the existing effective-input boundary clamps composed values to 1–100. Building another package creates an alternative; library entries never accumulate into a universal gain.

`PackageCreation` is an action in the existing `DevelopmentOpportunity`. Its free draft and quoted commitment use the same revisions, command fingerprints, saved ledger and single accepted decision as permanent work and Save. The exact `race-package-development` debit and decision are saved atomically. Insufficient funds consume no decision and do not silently become Save. Personnel are mapped from the frozen own roster; Manager/Technical efficiency affects only the bounded price. Matched quality and Development are recorded explicitly and inactive under this ticket's normal-only outcome policy.

`PackageDevelopmentQuote` freezes the template, content version, personnel, cost, timing, rules and normal outcome version. Preparation close saves one concrete `PackageDevelopmentOutcome` and immutable completed package version; pending commitments cannot be selected. Completed entries are materialised into the next event library without selecting them automatically. The original Base Car, permanent modifiers and active-weekend snapshots remain separate. Repeated close and next-lobby repair use the saved outcome; no second debit or reroll occurs.

The new contract uses optional `PackageQuote` fields on existing drafts/decisions and optional `PackageOutcomes` on `DevelopmentState`; they remain absent for older permanent work. Existing permanent quote/outcome versions and semantics are unchanged. `CampaignDevelopmentIntegrity` validates package quotes against their version, exact debit and frozen team personnel, replays every normal outcome, and compares completed library snapshots. Richer outcomes/refinement/Rush remain for S15 03 and require new versioned policies rather than reinterpretation of normal v1.
