# S15 04 — Rush and fair recorded policies

Canonical ticket: [#56](https://github.com/rociodevenish/BoxBox/issues/56). Based on integration `7cc8508f76adbf17a14a1adccebe459a09bb61ff`, including selection helper `407eef094c8fea94e8dd08b82c06f749713b2a17` and glossary integration `912f3ec`. Issue remains open for independent review.

Rush is an alternative commitment using the same opportunity and ledger as permanent development, package creation, refinement or Save. A `package-development-v3` quote freezes standard price plus six credits, personnel, changed distribution, intended event and the source version where applicable. The standard staff discount applies once; Rush adds no second discount or direct pace gain. Existing v1/v2 package and permanent outcome contracts retain saved dispatch.

The production neutral-personnel example costs 18 + 6 = 24 credits for Downforce. Normal/partial/breakthrough/compromised/delay probabilities change from 45/20/10/15/10 to 41/20/10/25/4 percent. Both aim at the intended preparation close: Rush raises the chance of reaching it from 90% to 96%, rather than promising a fictitious earlier event. A controlled zero-delay scenario explicitly says it cannot improve arrival chance. Rush uses the same project/opportunity/outcome-version class draw; there is no independent hazard or retry draw. Delay retains its saved specification and never repays.

Manager Development and matched Technical quality transfer at most ten percentage points into normal outcomes before Rush; Efficiency has the existing bounded shared discount/floor. Maximum staff makes the example standard 16, Rush 22 credits. Leadership, Operations and Race Engineers have no invented package speed effect. Reliability advice counts only when the actual target incident consumer is active; known future circuits are scored conservatively without assuming later activation.

The new project policy freezes public own-library, bounded car ratings, public fixed-calendar demand and all affordable normal/Rush creation/refinement alternatives. It compares expected marginal design fit against retaining the best existing free package, includes permanent work and Save, and reserves useful later spending where applicable. It uses no future entropy or opponent plans. The neutral Monaco worked example chooses standard Mechanical-grip, 16 credits, retaining 90 of 106. Older observations without package alternatives still replay the original v1 policy.

Free package selection has its own separate policy/history, independently implemented and merged from the helper. It compares completed own versions, preserves manual choices and existing assessment, runs before automatic practice, and freezes with qualifying. Assisted/Guided controllers can accept advice; Standard cannot access it. It never consumes a development opportunity or credits. Strict campaign integrity replays both distinct policies and frozen quotes.
