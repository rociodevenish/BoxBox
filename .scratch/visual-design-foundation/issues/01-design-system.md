# 01: Establish and validate the visual design system

**What to build:** A designer can review one coherent Broadcast visual system applied to representative driver cards, a public timing tower and a two-car controller before production components are built.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] Audit the recovered prototype and record patterns to reuse, adaptations and asset provenance; its unverified build is not assumed to be production-ready.
- [ ] Inspect the repository's shared design-asset collection at the start of work, including supplied driver imagery and any newly added track/other assets. Establish consistent portrait, crop, background and fallback rules using suitable real assets and document provenance and identity mapping.
- [ ] Establish semantic typography, colour, spacing, surface, radius, border, elevation and motion rules, including accessible focus, selected, submitted, locked, disabled, loading and error treatments.
- [ ] Preserve the selected charcoal/coral Broadcast direction and documented coral/gray portrait stripes; distinguish personnel role styling from team ownership.
- [ ] Define card anatomy, the five Simple driver attribute groups, preference tags, unknown values, compound badges, labelled estimates and race information hierarchy without inventing simulation conversions.
- [ ] Record dated recent F1 broadcast references and demonstrate recognisable timing-tower hierarchy adapted for readability.
- [ ] Apply the rules to representative card, timing-tower and two-car controller compositions at 360px, 768px and 1920×1080; inspect the layouts and record findings and deliberate departures.
- [ ] Establish WCAG 2.2 AA contrast, text alternatives to colour, visible focus, reduced motion and primary touch targets of at least 44×44 CSS pixels as the implementation baseline.
- [ ] Document the agreed visual baseline and extension points; later card categories remain deferred.
