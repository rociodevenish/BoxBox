# 06: Verify and document the integrated foundation

**What to build:** Developers can adopt a documented, reviewed visual foundation for the browser race, with reproducible gallery checks and explicit remaining limitations.

**Blocked by:** 04 — Build the two-car decision controller; 05 — Present phase outcomes and race finish.

**Status:** ready-for-agent

- [ ] The integrated gallery covers initial race, decisions, pending/ongoing stops, contextual battles, locked team, resolution, phase results and finish, plus long names, missing portraits, lap deficits and rejected input.
- [ ] Verify observable details, choices, summaries, lock/disabled behaviour, error recovery and keyboard access through the rendered gallery.
- [ ] Inspect a small stable screenshot set for cards, timing tower and controller at 360px, 768px and 1920×1080, including relevant orientation changes; record dimensions and review findings.
- [ ] Record contrast, focus, text alternatives, touch targets and reduced-motion checks and unresolved limitations.
- [ ] Record TV viewing-distance findings when a real TV playtest is available; do not claim desktop screenshots prove living-room readability.
- [ ] Build and type-check the frontend and verify gallery/controller entry points exclude the 3D renderer.
- [ ] Document tokens, anatomy, role/ownership styling, attribute semantics, interaction states, asset provenance, responsive usage, gallery execution and extension points without implementing deferred card categories.
- [ ] Document how to add supplied driver, track and other design assets, including identity mapping, provenance, packaging and fallback behaviour. Verify representative real assets and missing-image cases at supported layouts; full asset coverage is not required.
