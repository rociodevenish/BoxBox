# 05: Record replay and browser playtest evidence

**What to build:** A designer can reproduce browser race outcomes and assess whether two-car decisions, feedback and race pacing work for players.

**Blocked by:** 04 — Present events and continue through a complete race; segment-model evidence review and integration readiness; visual foundation 06 — Verify and document the integrated foundation.

**Status:** ready-for-agent

- [ ] Integrate reviewed segmented presets with equal/mixed 22-car fields on contrasting tracks; record readiness conclusions and model limitations.
- [ ] Designer-only replay records retain seed, configuration, model/randomness and opponent-strategy versions plus all accepted human/opponent decisions, separately from player payloads.
- [ ] Replay recorded decisions through the existing engine and verify authoritative phase/final outcomes match the browser session.
- [ ] Record decision, server resolution, presentation and total race durations separately; publish a reproducible playtest protocol and local multi-device run instructions.
- [ ] Complete short smoke and full-distance checks on contrasting tracks, including pending pits, legal battles, lapped finishes, eligibility and refresh/reconnect.
- [ ] Record actual player findings about comprehension, event explanations, both-car workload and pacing, with representative phone/display visual review.
- [ ] Treat 20–25 minutes as a measured player target; report unmet targets and corrective work explicitly. Automated clicks or server benchmarks do not establish enjoyment or pacing.
- [ ] Run relevant API/SignalR, browser, frontend build/type and existing simulation regression checks without duplicating private engine formulas.
