Ticket 01 automated implementation is complete. Hosted smoke, household playtest and real Firebase/Cloud Run cost evidence remain pending under ticket 07.

The replaceable `ISessionStore` boundary owns conditional persisted records. API hosts configure `Persistence:ProjectId`; `Persistence:EmulatorHost` or `FIRESTORE_EMULATOR_HOST` selects the local emulator. With no persistence project configured, existing isolated developer fixtures use a per-host volatile store. Production uses server-side application default credentials with the datastore scope; browser Firestore rules deny all direct reads/writes. SignalR remains the live transport.

Each manifest update compares Firestore updateTime and atomically publishes its immutable recovery chunks and removes superseded chunks. A chunk contains at most 160,000 UTF-16 characters (at most 640KB UTF-8); a supported recovery record is capped at 4MB. Growth past the cap pauses saving rather than assuming a race fits one Firestore document. Manifest readers retry up to three times when concurrent commits replace chunks. Precondition failures return409; storage outages return503. Failed writes roll memory back to the latest readable durable record, or its last confirmed cache if reads also fail.

A saved pending complete plan resolves deterministically and is committed once logically, then pauses for host resume. Existing committed outcomes and presentation/event identities are restored. Accepted command fingerprints/acknowledgements, phase/window revisions, team locks, Firebase UIDs, devices, assignments and control revisions are retained. Snapshots enforce restored current authority and filter private observations through the existing API/SignalR projections.
