# Circuit weather, version 1 (S10 ticket 01)

Weather is opt-in through nullable `RaceConfiguration.Weather`. Null is the all-dry regression mode: configuration, phase, team and public projection extensions are omitted and historical S08/S09 replay hashes retain their original model/randomness names. Enabled replays append `+circuit-weather-v1` and `+weather-sha256-v1`; saved tuning rejects an unsupported `ModelVersion`.

`CircuitWeather.Observe` is the shared preparation/session/race boundary: pass absolute simulation seconds, never wall-clock time. `RaceEngine` calls it with `WeatherTuning.TimeOriginSeconds + authoritative race time`. The race's existing earliest-event/exposure loop remains the sole clock; weather observations create no separate scheduler or random opportunity. A later qualifying/start slice can carry the same tuning, seed and absolute time origin into the race.

Rain is constant within fixed 60-second intervals by default. SHA-256 keys contain circuit-weather-v1, seed, immutable source version, interval ordinal and the rain channel. Rain clamps `MeanRain ± Volatility` to [0,1]. Wetness starts at `InitialWetness` and integrates `(rain × WettingPerSecond) − ((1 − rain) × DryingPerSecond)` over each actual interval, clamped to [0,1]. Evaluation starts from the same origin each time, so subdivision, strategy, diagnostics and repeated reads cannot accumulate rounding or reroll rain. Tuning validates finite bounds; observation supports one week of simulation time. These simple rates are authored hypotheses, with no spatial weather, temperature or meteorological calibration claim.

Current conditions are directly public: observed time, interval identity, rain intensity, wetness and drying rate. The simulation/configuration/seed are diagnostic inputs, never added to public snapshot payloads. `TeamObservation` includes current observations and only its team's forecast; PublicSnapshot includes conditions and no forecast. TeamSnapshot/OpenTeamSnapshot carry the private forecast. No hidden future list is serialized to these surfaces.

Forecasts use weather-forecast-v1 and are frozen at `floor(absolute time / ForecastRefreshSeconds)`, default 120 seconds. Their identity includes escaped team identity, the observed interval identity and issue time. The 300/900-second horizons state rain probabilities and bounded uncertainty ranges. Information quality is [0,1], narrowing estimate error/uncertainty but never producing perfect confidence. `CircuitWeather.Forecast` accepts only a legitimate current observation, team and quality; it cannot call or see future weather draws or the process seed. Holding those observations fixed while changing diagnostic future paths cannot change advice built from the observation. Future assistance remains ticket 05. Refresh/reconnect, command retry and replay-backed coordinator restart reproduce the same observation and forecast.

`WeekendPresetCatalog.WeatherInputs` snapshots the supplied track race-characteristic Weather Volatility ordinal with an explicit authored 1/2/3/4/5 map to .08/.16/.24/.32/.40 rain amplitude and records `weather-track-v1/1.0.0/2026.10.08-initial-balance/<track-id>`. This is not a conversion from headline stars. Reviewed inputs retain driver/track 1.0.0/2026.10.08-initial-balance and car-spec/1.0.0/2026.10.08-initial-model; wetWeatherSkill, tyreTemperature and detailed thermal/degradation demands remain unchanged for later effects. Ordinary live presets stay disabled until the complete wet-weekend integration; the test-only real API host can enable F1_WEATHER_FIXTURE=1.

Presentation labels “Observed conditions” separately from “Predicted rain” and states confidence, both horizons, issue/refresh simulation times and read stability in live text. The current collection contains 51 original files under assets/driver images and assets/track images; no new asset directories appeared. Existing portrait/track manifests provide stable identities, original hashes/provenance and packaged PNG/WebP variants. This slice reuses those portraits through raceDriverCard, keeps text/fallbacks and creates no new images or geometry.

This ticket establishes the process and information boundary. It does not change tyre compounds, suitability, incident rates, qualifying effects, starts or reaction windows. Later event detection must query these same intervals and consume their crossing times in the existing earliest-event loop.

The five optional profiles freeze all weather/tyre/reaction capabilities against the actual selected preparation circuit; human clarity/pacing acceptance remains unmeasured.
