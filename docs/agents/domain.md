# Domain docs

This repo uses a single domain context.

Before exploring, read:
- `GLOSSARY.md` at the repo root, if present.
- Relevant decisions under `docs/adr/`, if present.
- The existing design documents under `.docs/`.

Proceed silently when glossary or ADR files do not exist.
Domain modeling creates them as terms and decisions are resolved.

Use the glossary's vocabulary consistently.
Surface conflicts with existing ADRs explicitly.
Treat locked design decisions as the baseline; make proposed
changes explicit.
