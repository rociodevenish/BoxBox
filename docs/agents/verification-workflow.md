# Verification workflow

Run Node 24 (the existing package/runtime pin), the .NET SDK selected by `global.json`, and install locked dependencies with `npm ci --prefix src/frontend` and `npm ci --prefix tools/auth-emulator`. Install Chromium with `node src/frontend/node_modules/@playwright/test/cli.js install chromium` (CI adds `--with-deps`). No Firebase cloud login, credentials or Java is required: authentication checks use the pinned auth-only emulator and demo project. Port 19099 plus emulator hub 19400/logging 19450 must be free; an existing emulator is rejected rather than reused.

From repository root run `node tools/verify.mjs`. This runs tooling, typecheck, build, backend, gallery, browser, boundary and shared checks once, failing at the first failed step. After a fix rerun only affected named steps, for example `node tools/verify.mjs browser boundary`. Set `DOTNET_EXE` for a non-PATH SDK, `PLAYWRIGHT_BROWSERS_PATH` for an existing Chromium cache, and `F1_TEST_PORT`/`F1_API_PORT` to change isolated UI/API ports (defaults 4471/4571). All Playwright servers are owned by the test run and refuse existing listeners. Backend tests start/stop their own actual auth emulator; shared browser checks independently do the same.

Commands have bounded deadlines and process-tree cleanup. Each invocation keeps its completed manifest and per-command records under `.tools/reports/verification/runs/<run-id>/`; these remain unchanged by later focused runs. `progress.json` records an unfinished run, and `.tools/reports/verification/result.json` remains the latest-run compatibility pointer. Records contain launched PIDs, command identity, elapsed time, exit code and failure status. Use these recorded identities for cleanup; do not enumerate every Windows process. For other commands use `node tools/run-bounded.mjs --timeout-ms 60000 --report .tools/reports/task.json -- command args`. The runner only targets its own launched process tree, with cleanup bounded to five seconds.

Ordinary gallery captures write to ignored `.tools/reports/gallery`; Playwright artifacts and race captures also stay under ignored reports. Historical tracked evidence is not rewritten. Publish only reviewed, specifically named files using `node tools/publish-evidence.mjs .tools/reports/gallery .scratch/<effort>/evidence filename.png`. Capture source and destination are constrained to those respective roots. Existing standalone baseline capture scripts are explicit evidence-authoring tools, not part of verification.

Before broad regression checks, inspect one complete 360px phone flow and one 1920×1080 public display using focused browser tests. Record the viewport, capture path and assessment once in ticket evidence. Resolve visible layout problems before the single broad pass. After fixes run the affected checks rather than repeating every command.

Delegate only when the applicable skill or user permits it. Dispatch independent workers with `fork_turns: "none"` and compact ticket/file/SHA pointers, ownership and acceptance checks; inherit the model. Send milestone, blocker and final messages. Wait without rebuilding context or launching duplicate investigation. Preserve required independent Standards and Spec reviews with fresh concise scopes. A completion manifest should pin the integrated SHA, unique check results, inspected captures, preview ports and recorded PIDs. This reference does not add approval steps or change the repo's ticket implementation skills.

CI setup follows the official [setup-node](https://github.com/actions/setup-node), [setup-dotnet](https://github.com/actions/setup-dotnet) and [Playwright CI](https://playwright.dev/docs/ci-intro) documentation. Dependency versions remain the repository pins; CI execution is verified when the workflow runs on GitHub, not inferred from a local Windows pass.
