# Free Race Package selection policy

`public-package-demand-fit-v1` compares only a team's completed own package versions, its shared source car capabilities (Base Car plus completed permanent development), and public circuit demands. It receives no entropy, project draws, competitor plans or budget-spending operation. Selection is free and never commits development.

For each of the ten supported car capabilities, the policy sums strength and compromise, clamps the resulting source capability to 1–100, and weights the actual change by the corresponding circuit demand. The total is divided by 1000, bounding the score to −6..6. Aero maps to the corresponding cornering demand; tyre preservation/temperature map to degradation/thermal demand. Reliability receives weight 50 only when the configured mechanical-failure consumer has positive FailureRate; otherwise its weight is zero. There is no new cooling or temperature simulation. These weights are tuning hypotheses, not predicted lap seconds, incident probabilities or a claim that an inactive attribute grants pace.

Incomplete and circuit-inapplicable entries cannot be recommended. All comparisons retain their complete strength/compromise calculation rather than ranking only the headline benefit. Equal positive scores prefer ordinal package identity, then newest version; when no positive fit exists the explicit neutral version is selected. A valid completed neutral fallback is required. Multiple versions remain immutable; selection never merges them or equips multiple entries.

Automatic unclaimed/host-absent preparation selects before its own first Practice Assessment. Any prior explicit package choice (including neutral) is preserved. Existing practice also preserves its assessed context when the host applies absent-team preparation; later human selection still gives no new practice. Automatic and assisted/manual selection histories are separate from setup policy choices and development project choices. Histories save the policy version, legitimate observation, complete comparisons/recommendation and actual selected version; restored preparation replays those records and qualifying freezes them alongside the selected source.

Assisted and Guided private preparation exposes an observation-only recommendation. Accepting it requires the existing authorised controller, revision and help privileges, uses the existing retryable selection operation and records an assisted choice. It cannot spend credits or development opportunity. Standard projects no advice/history and rejects recommendation acceptance. Existing private device assignment, intentional Open family visibility and shared-tablet clearing remain authoritative. Selection never changes a qualifying-locked weekend or a historical assessed package.

Focused verification: `PackageSelectionDecisionPolicyTests` covers saturated capability/compromise trade-offs, pending/inapplicable exclusion, deterministic ties, missing fallback and inactive Reliability. `PackageSelectionGuidanceTests` covers Standard rejection, private assistance, separate automatic history and durable retry/restart through the public API; existing `RacePackageSelectionTests` retains the qualifying lock boundary. Browser integration and visual review are part of ticket56's combined campaign/preparation flow.
