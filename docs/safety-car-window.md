# Safety Car pit window (S09 ticket 03)

The incident result opens an identified `SafetyCar` decision window immediately, without advancing another ordinary Race Phase. The public banner contains only the observed incident identity, time, driver and kind. Own-car options identify available, queued, ongoing, retired and finished states. Queued/ongoing options include their committed compound. Retired/finished and committed cars require no command; teams with no free active cars do not hold the barrier. An empty human barrier commits the already frozen automatic choices immediately.

`SafetyCarTeamCommand` contains command identity, phase, revision and narrow per-car Stay Out/Pit/compound instructions. The special HTTP routes reject unrelated Pace/Battle fields. The existing mutation gate, durable acknowledgements, assignment authority, deadline generation and accepted-lock barrier remain authoritative. A repeated command returns its saved acknowledgement before current legality is rechecked. A conflicting reuse cannot change the lock. Missing teams receive their frozen observation-based choices; accepted plans remain locked across deadline expiry and recovery. The existing timing policy is retained: configured decision seconds plus the configured allowance for additional teams sharing one device (the reviewed fixture uses 90 + 30 = 120 seconds). This is provisional timing, not evidence of quick or comprehensible human play.

`RaceEngine.CommitSafetyCarChoices` atomically requires exactly the available active drivers. It queues new stops for their next lap end and never changes time, Classification, tyres or an existing commitment. `GetSafetyCarOptions` exposes public legal status, not hazard diagnostics. AI choices are frozen from existing legitimate team/timing observations before any human locks; the special conversion removes ordinary pace and battle decisions. Assisted and Guided players receive a saved pit-only recommendation from those same frozen choices, their own tyre estimates and the public incident/neutralisation facts. Advice offers only available cars, Stay Out/Pit and compound; it contains no Pace/Battle suggestion. Explicit auto-accept uses that saved plan only for a missing lock. Private own-car observations also include coarse component-condition and incident-risk bands; public display payloads omit these estimates. Legacy incident-free payloads omit the optional condition extension.

The slice intentionally stops at `safety-car-ready`. Ticket 04 owns neutralised running/restart and ticket 05 owns opening integration and the complete durable lifecycle. Live presets retain null incident tuning. Only the explicitly enabled developer `Game.BrowserFixtureHost` (`F1_SAFETY_CAR_FIXTURE=1`) registers the deterministic incident laboratory; no player command accepts a forced scenario.

Persistence records `WindowKind` and one `OperationKinds` entry per accepted plan; a pending plan dispatches using the saved window kind. Both restore and designer verification use `BrowserReplay.ResolveOperation`. New disruption exports use `browser-disruption-replay-v1`; ordinary exports remain `browser-dry-race-replay-v1` with the optional extension omitted. Old incident-free simulation hashes remain unchanged. Opening presentation now has an explicit saved cursor rather than inference from accepted-plan count. Ticket 05 owns migration of older opening-presentation metadata.

Presentation reuses the supplied portraits and stable display-only `raceDriverCard` mapping in published card order, with the existing manifest/runtime variants and text fallback. Original `assets/driver images` and `assets/track images` remain unchanged; no new raster is needed. The data versions and detailed input mappings remain those in `docs/local-incidents.md` (driver/track 1.0.0, 2026.10.08-initial-balance; car-spec 1.0.0, 2026.10.08-initial-model). Headline stars are presentation only and do not set risk or physics. The special controls omit the crowded nearby table and irrelevant Pace/Battle controls, preserve both driver identities and readable stop status, and work with reduced motion.
