# Opening and durable disruption recovery (S09 ticket 05)

An incident during the automatic standing start uses the same immutable interruption, simultaneous Safety Car window, real neutralised operation and normal-window restart as a mid-race incident. Its first special window is phase zero. The grid, frozen preparation, model version and hashed opening result remain available; the opening boundary reports the actual interruption time rather than claiming a completed lap. Observed major events remain visible through neutralised completion, including automatic continuation when both owned cars retire. Public Classification includes observed damage and retirement; no component exposure, thresholds, future draws or opponents' choices are projected.

Production composition leaves `IOpeningDisruptionPolicy` unregistered and ordinary presets retain null incidents. The explicit server policy accepts an authored circuit route and incident tuning, never a player command or forced scenario. Every enabled circuit needs its own validated route. The test-only host registers a Monza laboratory only when `F1_OPENING_DISRUPTION_FIXTURE=1`: 0.2 lap bypass, 38 seconds lane travel, unchanged stationary service, mechanical hazard 0.01/running second, zero additional component wear and major interruption enabled. These are deterministic stress-fixture coefficients, not calibrated live rules. Ticket 06 must assess rule/strategy evidence before any production registration and author/validate routes for every enabled circuit.

Historical ordinary opening presentations without the saved opening cursor migrate only when their explicit phase-zero presentation summary identifies the automatic standing start. No accepted-plan-count heuristic classifies opening presentations.

Real Auth/Firestore fault tests cover failure before and after the incident, special pending and neutralised commit; each checks duplicate commands, a second restart and designer replay.
